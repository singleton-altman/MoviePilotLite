# 音乐搜索实施计划

状态：规划草案；本轮仅建立计划，尚未开始功能实现。订阅及下载流程由用户后续补充。

## 目标与范围

在现有搜索入口增加音乐搜索 suggestion，展示歌曲、专辑、歌手搜索结果。复用当前登录会话、服务器配置、GetX 状态管理、主题和路由体系。第一阶段完成搜索与只读信息展示，第二阶段再接入完整歌曲订阅、资源搜索及下载流程。

## 已核对的现状

- 搜索首页由 search_index_controller.dart 构造本地 suggestion，search_index_page.dart 分组显示；当前不是远程自动补全。
- search_suggestion.dart 定义分类，跳转由 openMediaSearch 分发；新增类型时需同步分组集合、图标及跳转。
- 现有 media_search_list_controller.dart 使用影视模型，并自动查询订阅、入库状态及推断分页。直接复用会让音乐误入影视流程。
- 用户提供的响应包含 30 条数据：歌曲 recording、专辑 album、歌手 artist 各 10 条，本例全部来自 musicbrainz。不能据此断言另外两个来源不可用。
- 歌手的封面、年份、专辑信息可以为空，艺人列表也可能为空；年份为数字，音乐 ID 为字符串。歌曲 duration 示例为秒。

## 技术方向

采用“共享搜索入口、独立音乐模型和结果页”。相比给影视模型增加大量可选音乐字段，边界更清晰，能避免影视订阅副作用；相比单独创建完整搜索首页，则保留统一输入和历史体验。

### 1. 接口契约确认

- 按用户示例调用 GET /api/v1/media/search，title 为输入关键字，type 为 music，count 为 30。
- media_source 按重复查询键传递 musicbrainz、theaudiodb、doubanmusic；检查 ApiClient/Dio 的数组序列化，确保不会变成逗号字符串或带方括号的参数名。
- 使用当前服务器地址及现有鉴权、语言设置，不将示例服务器或令牌写入代码、测试、文档；无需复制浏览器专用请求头。
- 解析 success、message、data；业务失败和空结果分别处理。
- 已访问公共 Swagger 入口，但本轮未取得可核验的接口参数内容。实现前核对适配版本的 OpenAPI，确认三个来源、多来源聚合语义、count 限制及分页能力；与示例有差异时以目标服务版本契约为准。
- 示例无分页元数据；第一阶段只请求一次，不沿用影视“非空即可能有下一页”的推断逻辑。

### 2. 音乐数据及请求状态

- 新建音乐结果模型、搜索控制器和独立结果路由，沿用现有目录组织及依赖注入方式。
- 唯一身份由来源、音乐子类型、媒体 ID 组成；保留 artist_ids、album_id、isrc 等关联信息，供后续订阅和下载对接。
- 优先使用标准字段：标题、艺人、专辑、年份、时长、曲目数、封面、来源及详情链接。raw_data 不作为列表展示或身份识别依据。
- 艺人展示优先 artists，再回退 artist；封面优先 cover_url，再回退 poster_path，失败时使用本地占位图。
- 仅对相同复合身份去重，不按标题跨来源合并，不把歌曲与同名专辑视为重复。
- 处理空值、未知子类型、单条异常；异常数据不能让整页崩溃，缺失身份的条目不得进入后续操作。
- 关键字变化时取消旧请求或使用请求序号，防止迟到响应覆盖新结果；退出页面释放相关资源。

### 3. 搜索 suggestion

- 在现有媒体分组中增加“音乐 ‘关键字’”，副标题“搜索歌曲、专辑、歌手”，使用音乐图标，复用关键字高亮与点击样式。
- 输入为空不显示；点击携带当前关键字进入音乐结果页；默认键盘提交保持原有影视行为。
- 第一阶段沿用现有本地意图提示机制，不增加未提供契约的远程自动补全接口，也不在每次输入时请求三个音乐来源。
- 沿用现有文本搜索历史。音乐结果页内重新提交继续音乐搜索；首页选择历史文本后仍可选择音乐 suggestion。

### 4. 结果显示与交互

- 页面根使用 Scaffold，appBar 放标题及搜索入口，body 放加载、错误、空态和结果列表。
- 默认紧凑列表，提供“全部 / 歌曲 / 专辑 / 歌手”本地类型筛选和当前结果数量，保留服务端顺序；不把当前数量称为全库总数。
- 歌曲：方形封面、标题、艺人、专辑，可用时展示年份和分钟秒时长。
- 专辑：方形封面、标题、艺人，可用时展示年份、专辑类型、曲目数。
- 歌手：圆形头像或占位、名称，可用时展示地区和少量风格标签；不展示空白专辑行。
- 各类条目都显示类型和来源，区分同名结果；不显示无意义的零分、空字段或未经确认的音质信息。
- 点击条目暂定展示已有返回字段的只读信息弹层，不请求尚未提供的音乐详情接口；歌曲、专辑、歌手均不跳转影视详情。
- 第一阶段不展示可点击的订阅、播放或下载按钮，不触发影视订阅/入库查询。最终点击操作随第二阶段流程细化。
- 深浅色、中文长标题、无封面及大字体下都需可读；图片按原比例裁切，不拉伸。

## 实施顺序与验收

- [ ] 核对音乐搜索接口文档，确认重复来源参数与分页约束。
- [ ] 建立独立模型及请求控制器，覆盖业务失败、解析、身份和请求竞争。
- [ ] 增加 suggestion 分类、分组、图标、跳转及音乐路由绑定。
- [ ] 实现三类结果卡片、本地筛选、只读信息及加载/错误/空态。
- [ ] 使用精简且不含凭据的响应样例做模型与请求参数测试，验证歌曲时长、空歌手信息、同名不同类型及跨来源身份。
- [ ] 交互测试覆盖 suggestion 跳转、筛选、重试、连续搜索及返回；确认音乐搜索不调用影视订阅或入库接口。
- [ ] 验证重复查询键实际编码正确，不重复加载首批结果；检查 iOS/Android、小屏、大字体和深浅色布局。
- [ ] 运行相关静态分析与测试，更新 CHANGELOG；不更改应用 ID，不升级无关依赖，不重新生成已知有问题的模型文件。

## 第二阶段待用户提供

1. 歌曲、专辑、歌手各自是否支持详情和订阅，以及接口、请求体、响应、状态查询、取消/删除行为。
2. 音乐结果到资源搜索的身份映射；站点选择、下载器、目录及音质规则如何传递。
3. 下载结果选择、创建任务、进度、失败重试与已订阅/已入库提示的完整流程及示例。

这些信息用于扩展后续操作，不阻碍第一阶段模型、suggestion 与结果展示设计；收到后补充本计划再实施对应流程。
